# VGGT-Omega 接入（2.0 开发版）

新建任务默认使用 **VGGT-Omega**，可手动选择 **GLOMAP** 使用旧版完整几何重建流程。界面与常用命令行只提供这两个选项，均不会静默切换到其他解算器。VGGT 仍处于实验验证阶段。

首次升级会将新任务默认项迁移到 VGGT-Omega，随后尊重已保存的选择。历史任务保留原求解器及参数。COLMAP Global Mapper 与原生动态焦距 BA 的研究代码和底层源码保留，参见 [研究归档说明](COLMAP-RESEARCH-ARCHIVE.md)。

支持视频和图像序列；视频先按任务帧率抽帧，图像序列直接读取。VGGT 分支不运行 SIFT、匹配数据库、GLOMAP 或 COLMAP 求解。每一张输入帧均参与模型推理，不用插值冒充预测。

VGGT 任务隐藏“处理分辨率”，视频按原尺寸拆帧，输入尺寸统一由“推理档位”控制（低 384、中/高 512，显存保护可能进一步调整）。处理帧率仍决定参与推理的帧数。切回 GLOMAP 后恢复“处理分辨率”和“计算精度”；已有缩放参数不会被带入 VGGT 推理。序列帧导出在 VGGT 下使用原始视频分辨率，Blender 继续引用项目里的原尺寸背景帧。

## 本机使用

通过 `Start-Dev.bat` 或 `Start-Dev-CUDA.bat` 启动本仓库开发版。VGGT 的 GPU 开关独立于 COLMAP 启动器：开启硬件加速后使用“设置”中选中的 CUDA GPU，关闭后使用 CPU。

工作区已有以下文件，无需重新下载权重：

```text
工作区/
  src/Seedom/
  third_party/
    vggt-omega/                  # 官方源码，保留 LICENSE
    models/VGGT-Omega/
      vggt_omega_1b_512.pt
      LICENSE.txt
      DOWNLOAD.json
```

开发版的 Python 位于工作区 `archive/legacy-1.x/runtime/python/python.exe`，与求解器启动器共用同一运行库。设置和任务记录会保留该外部路径，不会因工作区名称为 `GLOMAP GUI` 而将它迁移到 `src/Seedom/archive/`；旧记录中误存的这类相对路径会自动恢复。显式指定且不存在的自定义 Python 路径仍会报错，并显示具体路径。

已验证的核心运行环境：Python 3.13.11、PyTorch 2.9.1+cu130、NumPy 2.3.5、Pillow。本适配仅使用官方相机/深度模型核心，以等价的 PIL/NumPy 转换代替 torchvision 的 ToTensor；没有安装 upstream demo、训练和评测依赖，也不要求 nvcc 或 C++ 编译。上游完整 demo 的依赖要求见其自己的 requirements/pyproject。

## 可移植配置

默认也支持把源码放进 `runtime/vggt-omega/`，权重放进 `runtime/models/VGGT-Omega/vggt_omega_1b_512.pt`。模型本身不加入 Git，也不自动下载。

如需在别的磁盘共用同一份权重，可设置 `config/vggt-runtime.json`，路径可以是相对软件根目录的路径或绝对路径：

```json
{
  "source": "E:/GLOMAP GUI/third_party/vggt-omega",
  "checkpoint": "E:/GLOMAP GUI/third_party/models/VGGT-Omega/vggt_omega_1b_512.pt"
}
```

环境变量 `SEEDOM_VGGT_SOURCE`、`SEEDOM_VGGT_CHECKPOINT` 优先于该配置。显式指定的路径失效时会报错，不会静默换用另一份权重。

## 显存和长视频

| 计算档位 | 模型最长边 | 每批最多帧数 |
| --- | ---: | ---: |
| 低 | 384 | 8 |
| 中 | 512 | 12 |
| 高 | 512 | 20 |

默认沿用当前任务预设。每批保留 4 帧重叠，用重叠相机的方向共识确定旋转、对应像素的稳健深度比确定尺度、相机中心确定平移，对整批结果应用同一个 Sim(3) 变换。这样避免单独拟合深度点云时，把模型在不同批次中的深度形变误当成相机运动。仍检查对应点误差及重叠相机的位置、方向；对齐失败会停止，日志记录帧号和偏差。不会把不相连的镜头硬拼为一条轨迹。

根据所选显卡的当前空闲显存限制批次；显存不足时缩小批次重试，首批还可以降低推理分辨率，不会偷偷改用 CPU。模型加载采用 mmap + meta + assign，避免在内存里额外分配一整份权重。CPU 推理可用，但 1B 模型可能很慢。

对齐不通过时，自动增加已有帧的重叠范围，并尝试保留较早的参考帧；重试受当前批次容量和保留历史限制，不会无限循环。只有通过原有深度、相机方向和位置检查后，才写入新帧。已导出的相机不会因重试而重复写入。重叠深度参考可随已通过检查的上下文更新，已导出的相机和点云保持不变。

2026-11-28 的 446 帧快速变焦素材仍未通过完整视频验证：原先在第 165 帧连接失败，自适应重叠重试后在第 174 帧停止。将该素材从 30 fps 降至 10 fps 后仍在变焦段失败，因此降低帧率也不是此素材的已验证解决办法。增加重叠不能保证解决预测不一致；此情况尚未修复，不能据此宣称长视频或快速变焦支持稳定。

内存只保留当前批的深度及重叠区域；深度采样点流式写出，全项目最多 250,000 个，每帧最多 2,000 个，不为视频每个像素保存点云。停止任务会终止推理子进程并释放显存。

**先测试单镜头短片。** 长视频只是局部批次对齐，没有全局 BA、回环优化或自动独立镜头重建；存在累积漂移，不能保证变焦、低视差、纯旋转、动态物体或切镜素材的轨迹质量。建议有切镜的素材先拆成独立镜头。

## 输出和 Blender

沿用项目结构：`point could/` 存放标准 COLMAP BIN/TXT 模型、彩色 PLY 和 `vggt-report.json`，日志放在 `log/`。成功完成所需导出后，清理 `_cache/` 中的计算图像、数据库与求解中间结果，只留下源素材和结果的轻量 JSON 记录。失败、停止或 Blender 导出失败时保留计算缓存。

添加任务分为「输入素材 → 解算设置 → 导出」。序列帧属于 Blender 导出，自动、手动导出共用同样的参数：JPG、PNG、无损 WebP、TIFF；原尺寸、1/2、1/4、1/8，或按高度限制到 2160p、1440p、1080p、720p、480p（保持比例，不放大）。图像序列输入也能转换为 Blender 背景素材。

背景素材保存在 `video/<格式-尺寸-标识>/`，不同规格独立保存，已有 `.blend` 使用的序列不会被再次导出覆盖。相机内参和解算帧率不受导出尺寸影响，合成器将背景缩放到场景尺寸。关闭序列帧会同时关闭背景；不导出 Blender 时只保存模型、点云、日志和项目记录。

缓存清理后仍可手动生成 Blender 工程：已有相同规格序列会直接复用，其他规格从原视频或图像序列生成。请保留原素材；没有原素材和已有序列时，可以关闭序列与背景，只导出相机和点云。原始图像序列目录不会被清理。历史 `.blend` 若引用旧缓存，应继续保留原来的缓存，本次不会扫描清理历史项目。

模型相机使用 OpenCV camera-from-world 坐标，逐帧 PINHOLE 内参保留原图分辨率、缩放和中央裁剪的逆变换。点云来自置信度筛选后的**单视图预测深度**，并非多视图三角化轨迹；模型与点云只有相对尺度。摘要不把自投影为零的误差当作测量精度。

Blender 支持逐帧焦距，但渲染像素宽高比不可动画。导出使用中位像素比例，保留完整原始内参到场景 `camera_parameters`；比例随帧变化造成的近似误差另外存入场景及导出报告 `pixel_aspect_approximation_px`，不会混入坐标转换校验误差。该误差以画面 10%–90% 范围的验证射线计算，非对真实物体的精度保证。
